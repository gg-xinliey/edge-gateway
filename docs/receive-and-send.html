Sequence · Edge Gateway (RES API – TCP)

How we receive data, answer the adapter, and send to MES

Adapter gets back

Answers on the same connection

  • {"ack":id} once the line is on disk (ms)
  • Same message_id again: the first copy's answer, nothing new to MES
  • No machine_id: {"nack":id,"reason":"no machine_id"}
  • Not valid JSON, message_id readable: {"nack":id,"reason":"not valid JSON"}
  • Unchanged values: still ack, no record
  • Unknown tag: ack; the known tags go to MES, the unknown one is left out and listed under Unidentified

No reply

Adapter keeps the line

  • Machine has no tab: held until registered
  • Tag not mapped, only with unmappedTags = hold
  • No message_id, or broken JSON without one
  • IO / motion lines: never answered
  • Line over 1 MB with no line break: connection closed
  • Resend: after it reconnects (its own interval). Held machines are disconnected once fixed, so they resend at once

MES answer

What happens to the row

  • Payload: only the MES table columns (null when no tag). Extra fields and record_timestamp are not sent; tags joined with + arrive as one value, 001_xxxx
  • 2xx: sent. 409: MES has it already, counted as sent
  • 5xx, timeout 15 s, 401/403/407/408/429: retry, wait 2 → 4 → 8 → 16 → 32 → 60 s, then every 60 s, no limit
  • Back to 2 s as soon as MES takes a row, so the backlog starts within 60 s of MES coming back
  • Other 4xx: failed messages, no auto resend; re-send or discard on the page
  • Gateway crash before a row is marked sent: sent again with the same event_id; MES must drop the repeat
